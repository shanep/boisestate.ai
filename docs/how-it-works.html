How it works

Claude Code only knows how to talk to Anthropic's API. boisestate.ai has its own API that works differently. The plugin runs a small bridge on your computer that translates between the two, so Claude Code never knows the difference.

The big picture

There are three programs involved. boisestate is the command you type. It starts the bridge, a tiny web server that only your own computer can reach, and then starts the normal Claude Code app pointed at it. Every request Claude Code makes goes to the bridge, and the bridge sends it on to boisestate.ai with your API key.

What boisestate does

A Claude Code plugin can add commands and hooks, but it can not change where Claude Code sends its requests. That is read once when Claude Code starts. So boisestate wraps claude, and it does these five things every time you run it:

1. Read your keyFrom the keychain, never from a file in your project.
2. Start the bridgeOn 127.0.0.1 with a random port and a random password.
3. Start claudePointed at the bridge, with your args passed along.
4. You workClaude Code works just like it always does.
5. Clean upWhen claude exits, the bridge stops too.

Here is exactly what claude gets in step 3:

SettingValueWhy
ANTHROPIC_BASE_URLhttp://127.0.0.1:<port>Sends every request to the bridge
ANTHROPIC_AUTH_TOKENa new random value each runOnly this Claude Code can use this bridge
ANTHROPIC_API_KEYremovedSo a real Anthropic key can never leak through

--permission-modedefaultAuto mode is switched off, see below

You can still pick your own model and mode, for example boisestate --model sonnet or boisestate --permission-mode plan. The only thing it overrides is auto mode.

One turn, step by step

Let's follow one question that needs a tool. We ask Claude what the first heading in README.md is. The model can't read files itself, so it asks Claude Code to run the Read tool, and then answers. That one question is two calls to boisestate.ai.

Tools as text

This is the trickiest part of the bridge. Anthropic's API has tool calling built in: Claude Code sends a list of tools, and the model can answer with a structured tool_use block. boisestate.ai's API does not have tools at all. It takes text and gives back text.

So the bridge writes the tools into the system prompt as plain text, along with instructions for how to call one. Here is the same request on both sides of the bridge.

Claude Code sends the bridge
POST /v1/messages
{
  "model": "claude-opus-5-5",
  "system": "You are Claude Code...",
  "tools": [
    { "name": "Read",
      "input_schema": { ... } },
    ... 11 more tools
  ],
  "messages": [
    { "role": "user",
      "content": "What is the first
                  heading in README.md?" }
  ],
  "stream": true
}
The bridge sends boisestate.ai
POST /api/chat/api-converse
X-API-Key: your key
{
  "model_id":
    "global.anthropic.claude-opus-5-5",
  "system_prompt": "You are Claude Code...
# Calling tools
To call a tool, write a block
exactly like this ...
# Tools
## Read ...",
  "messages": [ same messages ],
  "stream": true
}

The model answers with a tagged block of JSON. The bridge finds it, checks that it is a tool Claude Code actually offered, and turns it into a real tool_use block. If the model writes text before the block, that text goes to you as normal.

boisestate.ai replies with text
<tool_call>
{"name": "Read",
 "input": {"file_path":
   "/home/you/proj/README.md"}}
</tool_call>
Claude Code gets a real tool call
{
  "type": "tool_use",
  "id": "toolu_6f1c...",
  "name": "Read",
  "input": {"file_path":
    "/home/you/proj/README.md"}
}

On the next call, the tool's result goes back the same way, as a <tool_result name="Read"> block of text. A live test of 40 different requests through boisestate.ai, with Claude Code's full prompt and tools, parsed every single reply.

The catch is that the tool list is text, so it is sent with every call. With native tools that is also true, but here it is about two thirds of every request. That is why MCP servers are off: each one adds more tools to every single call.

Where your quota goes

boisestate.ai charges by the token, a chunk of text about 4 characters long. You pay for tokens in (everything sent to the model) and tokens out (what it writes back). Opus 5.5 costs $4 per million tokens in and $20 per million out, and Sonnet 5 costs half that.

Why auto mode is off

Auto mode lets Claude Code approve its own tool calls. To do that safely it asks a second model to check each step. Through the bridge that was about six extra 55,000 token calls to Sonnet per turn, which used up a month's quota in under an hour.

Quota warnings

boisestate.ai's usage page needs a browser, so the bridge keeps its own count. After every call it writes one line to a log with boisestate.ai's own token counts, then adds up the month. If you have just crossed 80% or 100%, you see a warning when Claude finishes its turn.

Call finishesboisestate.ai reports the tokens it used
Log itOne line in usage.jsonl
Add up the monthPriced at boisestate.ai's rates
Crossed 80% or 100%?Write a notice for this session
Stop hookShows the warning at the end of the turn

Every session on your computer logs to the same file, so two terminals running at once still add up right. Each warning shows once, the first time you cross it. When boisestate.ai refuses a call because the quota is gone, it says exactly what you have spent and what the limit is, and the bridge saves that too, so the next estimate starts from the real number.

Keeping your key safe

Your API key is basically your credit card for boisestate.ai, so it lives in the safest place your computer has and goes to as few programs as possible.

BOISESTATE_API_KEYIf this is set, it wins. Handy for CI.
macOS keychainOr the Linux keyring through secret-tool
Private fileLinux without secret-tool, readable only by you

Claude never sees it

The key goes to the bridge and nowhere else. It is removed from the environment Claude Code runs in, so a tool can't print it by accident.

Only your computer

The bridge listens on 127.0.0.1, which other computers can't reach, and wants a random password that changes every run.

Never on the command line

boisestate login hands the key to the keychain on standard input, so it never shows up in your shell history or the process list.

Limits

boisestate.ai's API is simpler than Anthropic's, so a few things work differently.

ThingWhat happens
ImagesDropped. boisestate.ai's API only takes text, so pasting a screenshot does nothing.
Long answersboisestate.ai stops any single request after about 60 seconds.
Context gaugeAn estimate at 4 characters per token, since boisestate.ai has no way to count tokens ahead of time.
Temperature and similar settingsNot sent. boisestate.ai rejects them.
MCP serversOff, since their tools would ride along in every call.

Using the bridge alone

The bridge also speaks the OpenAI chat API, so other tools and your own scripts can use boisestate.ai through it too. boisestate bridge runs it in the foreground until you press Ctrl+C. Set BRIDGE_PORT to pick the port and BRIDGE_TOKEN to require a password.

Terminal
$ BRIDGE_PORT=8787 boisestate bridge
{"ready":true,"port":8787}
Another terminal
$ curl -s http://127.0.0.1:8787/v1/chat/completions \
    -H 'content-type: application/json' \
    -d '{"model": "sonnet", "messages": [{"role": "user", "content": "Say hi"}]}'
RouteAPI
POST /v1/messagesAnthropic Messages, what Claude Code uses
POST /v1/messages/count_tokensAnthropic token count (an estimate)
POST /v1/chat/completionsOpenAI chat completions
